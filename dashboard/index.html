§01 One recorded run, node by node

A successful-looking write is not a completed write.

ProcureFlow turns a request email or a supplier quote into a Material Request, a Purchase Order, an approval, a goods receipt and a Purchase Invoice in ERPNext, then matches order, receipt and invoice. Every write is read back and compared with what was sent before the run moves on, and every decision cites a rule in the written policy.

    §03

    The approval receipt

    An approval is given to an order as it looked at that moment. The gate records a digest of what the approver saw; just before submitting, the order is read back from the ERP and the digest recomputed. If they differ, the approval is void (R12).

    Should stop, did stop

    Each scenario states the outcome it expects. A run that should have stopped for a person and did not is false-touchless: the costly mistake, so it is counted first. A run that stops when it should not is a false stop: annoying, not dangerous.

      §05

      The policy is a document

      No threshold lives in the code. The agent parses policy/procurement_policy.md and cites a rule id on every decision. The count beside each rule is how many scenarios cite it in their recorded rules, out of the whole v3 suite.
